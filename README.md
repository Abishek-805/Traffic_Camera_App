# Traffic Camera Node (Mobile Camera Application)

An edge vision sensor client for the **[Smart Traffic Management System](https://github.com/Abishek-805/Smart-Traffic-Management)**. This Android application turns a physical smartphone into an intelligent traffic camera node, streaming synchronized frames and telemetry to the backend inference coordinator over a trusted local area network (LAN).

---

## Overview

The Traffic Camera Node captures live approach traffic at an intersection and transmits video frames to the central backend. Each connected device is assigned to one intersection approach direction (`NORTH`, `SOUTH`, `EAST`, or `WEST`). The app supports dynamic pairing via QR codes generated by the backend dashboard, real-time WebRTC video streaming, and adaptive telemetry reporting.

---

## Architecture

- **Runtime**: React Native `0.81.5` on Expo SDK `~54.0.0` (Bare / Custom Native Build).
- **Video Transport**: WebRTC video streaming powered by `react-native-webrtc` (`124.0.8`) with signaling performed over an authenticated WebSocket connection (`/ws/camera`).
- **Signaling & Handshake Protocol**:
  1. Phone connects to backend WebSocket at `ws://<SERVER_HOST>:<PORT>/ws/camera`.
  2. Phone sends `REGISTER_CAMERA` with node ID, hardware capabilities, and QR secret.
  3. Server validates credentials and returns `REGISTER_ACK` with an issued session token.
  4. WebRTC session negotiation begins via `WEBRTC_OFFER`, `WEBRTC_ANSWER`, `WEBRTC_ICE`, and `WEBRTC_STOP`.
  5. The active camera stream screen (`StreamingScreen.tsx` -> `WebRTCPreview.tsx`) runs WebRTC directly. If WebRTC negotiation or ICE discovery fails (e.g. non-routable LAN candidate), it fails cleanly with an observable error and manual retry action without silent transport degradation.
- **Snapshot Capture Engine**: `CameraStreamingService.ts` / `UploadWorker.ts` provides a serial JPEG snapshot pipeline with strict processed-frame backpressure (`FRAME_ACK`), bounding memory and queue size.

## Fresh Machine Setup

Follow these exact steps on a clean clone:

```powershell
# 1. Clone the repository
git clone https://github.com/Abishek-805/Traffic_Camera_App.git
cd Traffic_Camera_App

# 2. Install dependencies (runs patch-package via postinstall)
npm ci

# 3. Create environment configuration
cp .env.example .env

# 4. Verify TypeScript types and protocol suites
npm run type-check
npm test
```

> [!NOTE]
> **Automatic VisionCamera Native Patch**:
> `npm ci` triggers the `postinstall` script, which executes `patch-package`. This applies `patches/react-native-vision-camera+5.2.2.patch`, fixing the React Native 0.81 `RawProps` JSI cast crash (`PreviewView.previewOutput: Cannot cast dynamic to a jsi::Value`).

## Environment Configuration

Copy `.env.example` to `.env`. The mobile application reads environment variables with the `EXPO_PUBLIC_` prefix:

| Variable | Purpose | Default | Required / Optional | Used By |
|---|---|---|---|---|
| `EXPO_PUBLIC_SERVER_HOST` | Fallback backend IP or hostname | `''` (empty string) | Optional | `src/utils/constants.ts` |
| `EXPO_PUBLIC_REST_PORT` | Fallback REST API port | `8000` | Optional | `src/utils/constants.ts` |
| `EXPO_PUBLIC_WEBSOCKET_PORT` | Fallback WebSocket port | `8000` | Optional | `src/utils/constants.ts` |

```ini
# .env example
EXPO_PUBLIC_SERVER_HOST=192.168.1.100
EXPO_PUBLIC_REST_PORT=8000
EXPO_PUBLIC_WEBSOCKET_PORT=8000
```

> [!WARNING]
> Never set `EXPO_PUBLIC_SERVER_HOST` to `127.0.0.1` or `localhost`. On Android, `localhost` refers to the mobile phone itself. Always supply the backend workstation's local network IP address (e.g. `192.168.1.50`).
> Note: When pairing via QR code, the host, port, protocol, and credentials are dynamically extracted from the QR code payload, overriding static defaults.

## Android Device Setup

1. On your physical Android phone, navigate to **Settings** -> **About Phone**.
2. Tap **Build Number** 7 times to enable **Developer Options**.
3. Open **Developer Options** and enable **USB Debugging**.
4. Connect the phone to your computer via USB cable.
5. In your terminal, verify ADB detects the device:
   ```powershell
   adb devices
   ```
6. Grant USB debugging permissions on the phone prompt if requested.
7. Connect both your phone and PC to the **exact same Wi-Fi network / subnet**.

## APK Build

Download the resulting `.apk` file directly onto your phone.

## Backend Connection

```
[ Android Camera Node ]  ---(Wi-Fi / LAN)--->  [ Smart Traffic Management Backend ]
                                                 REST API:  http://<LAN_IP>:8000
                                                 WebSocket: ws://<LAN_IP>:8000/ws/camera
```

### Pairing Flow:
1. Start the companion backend on your PC: `.\start.ps1 -Lan` (or `python run.py --host 0.0.0.0 --port 8000`).
2. Open the Web Dashboard at `http://localhost:8000` (or `http://<LAN_IP>:8000`).
3. Navigate to **Live Cameras** -> **Pair Camera Node**.
4. Select an approach direction: `North`, `South`, `East`, or `West`.
5. Click **Generate QR Code**.
6. In the mobile app, tap **Scan QR Code** and scan the code displayed on the screen.
7. The app connects to `/ws/camera`, authenticates with the QR secret, obtains an issued session token, and starts the stream.

## Camera Configuration

- **Approach Allocation**: Exactly one phone camera connects to each intersection approach (`NORTH`, `SOUTH`, `EAST`, `WEST`).
- **Camera Selection**: Defaults to the rear-facing camera (`back`).
- **Cadence & Resolution Presets**:
  - **Low Power (2 FPS)**: Optimized for thermal safety during extended operations.
  - **Balanced (4 FPS)**: Standard setting for active traffic flow analysis.
  - Longest edge limits: `640px` (recommended for 4 concurrent feeds on CPU backend), `1280px`, or `1920px`.
- **Screen Awake**: Screen stays awake automatically while actively streaming (`expo-keep-awake`).

## Troubleshooting

### `PreviewView.previewOutput: Cannot cast dynamic to a jsi::Value`
- **Cause**: VisionCamera 5.2.2 lacks Nitro's React Native 0.81 RawProps compatibility parser.
- **Solution**: Run `npm ci`. Ensure `patch-package` runs and applies `patches/react-native-vision-camera+5.2.2.patch`.

### `Connection Refused` or WebSocket Fails to Connect
- **Cause**: Mobile phone cannot route packets to the PC's host address or port.
- **Solution**:
  1. Confirm PC and phone are on the exact same Wi-Fi SSID / subnet.
  2. Verify PC's LAN IP with `ipconfig`.
  3. Ensure Windows Defender Firewall allows incoming connections to Python / Node on port 8000 (and 8001 if using split server).

### `QR Code Expired`
- **Cause**: QR pairing secrets have a 5-minute time-to-live window.
- **Solution**: Click **Generate QR Code** again on the web dashboard to produce a fresh code.

### `WebRTC video is not connected` / ICE Timeout
- **Cause**: The phone could not find a direct UDP route to the backend server.
- **Solution**: Tap **Retry WebRTC** on the streaming screen. Ensure no corporate client-isolation firewall blocks UDP traffic between LAN devices.

## Known Limitations

1. **Approach Single-Tenancy**: Only one camera can be connected to a given approach direction at any time. Connecting a second node to the same direction requires disconnecting the first.
2. **Network Security**: Cleartext HTTP and WebSocket protocols are utilized for trusted local prototype LAN environments. Do not expose these endpoints over the public internet.
3. **Local Release Signing**: Standalone local APK builds use the default Android debug keystore; configure production signing credentials before public distribution.
